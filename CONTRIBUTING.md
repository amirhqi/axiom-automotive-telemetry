# Contributing

Thanks for taking the time to improve AXIOM.

## Before opening a change

- Keep changes focused and explain the engineering reason.
- Add or update tests when behavior changes.
- Run the full test suite locally.
- Avoid committing build output, generated binaries, logs or local Qt Creator state.
- Update documentation for user-visible or architectural changes.

## Pull requests

A useful pull request includes:

- Problem/motivation
- What changed
- Design trade-offs when relevant
- How it was tested
- Screenshots for UI changes

## Coding style

Follow the repository `.clang-format` and `.editorconfig`. Prefer maintainable code over clever abstractions.

## Branches

Use short-lived branches such as `feature/socketcan`, `fix/tcp-framing`, or `docs/linux-build` and merge through pull requests when collaborating.
